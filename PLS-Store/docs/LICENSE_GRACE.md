# AutoStars 2.3: запас на сбой проверки — 12 часов

Магазин выдаёт подписанное подтверждение после успешной проверки ключа и FunPay ID.
В нём фиксируются отпечаток ключа, FunPay ID, продукт, время выдачи и срок окончания
через **43 200 секунд (12 часов)**. Подтверждение проверяется публичным ключом,
встроенным в скачанный `.py`. Кеш сохраняется локально в
`storage/plugins/AutoStars/license_status.json` с правами 0600; секреты Fragment,
seed-фразы и кошельки в него и в запрос проверки не попадают.

## Поведение

- Первая установка требует доступного сервера и успешной проверки.
- В нормальном режиме плагин проверяет доступ перед защищёнными операциями,
  переиспользуя результат до 60 секунд.
- Ошибка подключения/таймаут, HTTP 404/408/429 или 5xx позволяют использовать
  прежнее подписанное подтверждение, если оно ещё действительно. Некорректный
  JSON при HTTP 200 также рассматривается как временный сбой сервиса.
- Повторные сбои не продлевают подтверждение. Повторная попытка связи идёт
  примерно раз в минуту при операциях, без сетевого таймаута на каждый заказ.
- Явный отказ, HTTP 400/401/403, `valid:false` или неверная подпись аннулируют
  кеш. После перезапуска он не включит временный режим для отказанной лицензии.
- Кеш для другого ключа, FunPay ID или адреса проверки не подходит. Смена аккаунта
  требует новой онлайн-проверки. Переход на другой хостинг с тем же FunPay не
  привязан к IP, но без переноса кеша тоже потребуется связь с сервером.
- Перезапуск Cardinal сохраняет запас при наличии файлов, корректного времени
  и прав записи. Некорректный/просроченный кеш, заметный перевод часов назад
  или недоступное для записи хранилище не дают временный доступ.
- Истечение 12 часов останавливает продажи до успешной проверки. Уже начатый
  внешний перевод Stars этим не отменяется.

Пример: последний успех в 12:00, сервер перестал отвечать в 12:10. Без новых
успешных проверок работа разрешена до 00:00, а не до 00:10. Если сервер снова
успешно подтвердил ключ в 18:00, новый срок — до 06:00 следующего дня.
В `/autostars_license` видны временный режим и оставшееся время.

Если связи нет, клиент не может узнать о новой блокировке: задержка её применения
может достигать остатка 12 часов. В открытом Python можно изменить логику или
восстановить старые локальные файлы; абсолютная защита не заявляется.

## Обновление на BotHost

1. Обновите код из `main` и зависимости магазина:
   `pip install -r requirements.txt` из `PLS-Store/`. Серверу добавлена библиотека
   `cryptography`; **на хостинге Cardinal её устанавливать не нужно**.
2. Перезапустите магазин. Ключ подписи автоматически создаётся при первой
   необходимости в **каталоге базы данных**, файл `license_approval_key.pem`.
3. Этот файл должен находиться на постоянном диске вместе с SQLite и входить
   в резервную копию. Не публикуйте его и не передавайте покупателям. Если файл
   повреждён, он не заменяется молча новым ключом.
4. После обновления скачайте AutoStars 2.3 через «Лицензии» без новой покупки,
   замените файл в Cardinal и перезапустите его. Встроенная поставка обновляется
   вместе с магазином. Если в админке загружалась собственная копия, обновите
   именно её через Товары → Файл, версия и инструкция.
5. Пока сервер доступен, откройте `/autostars`, чтобы получить первое подтверждение.
   Старый AutoStars 2.2 не получит новый механизм автоматически.

Публичный ключ встраивается при выдаче файла. Если приватный ключ потерян/сменён,
новые подписи не совпадут со старым публичным ключом: покупателям понадобится
скачать обновлённый `.py`. Поэтому сохраняйте `license_approval_key.pem` при
переустановке и переносе магазина. Отдельный сервер или новые токены не нужны.

Подпись RSA-2048/SHA-256 проверяется в плагине стандартной библиотекой Python.
В магазин по-прежнему передаются только `key`, `funpay_id`, `product`.
Старые клиенты совместимы с расширенным ответом API, но без 12-часового режима.
