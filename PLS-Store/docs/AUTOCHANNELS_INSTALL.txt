PLS Store · AutoChannels 5.0.0 · 399 ₽ навсегда
Бессрочная лицензия на один FunPay-аккаунт.
Исходный автор Ch AutoDelivery: @uservkru. Сборка и оформление: PLS Store.

1. Установка и резервная копия
Нужны работающий Cardinal и его Telegram-бот с авторизованным администратором.
Остановите Cardinal. Сохраните всю storage/plugins/ и session_channel.session
(в рабочей папке Cardinal), включая config, tiers, stock и старый pending.
Уберите ch_autodeliv.py и его дубли из plugins/, сохранив копию вне этой папки.
Поместите AutoChannels.py в plugins/. Не запускайте его отдельной командой.
Зависимости: telethon, requests, qrcode[pil]; библиотеки FunPayAPI и telebot
обычно предоставляются Cardinal. Установите их в окружение Cardinal до запуска.
Файлы настроек, склада и тарифов сохраняют прежние имена ch_autodeliv_v3_fresh*,
чтобы обновление не потеряло ваши данные. Новая лицензия и журнал:
storage/plugins/AutoChannels/license.json, license_status.json, orders.json.
Старые ожидания без проверяемого покупателя/заказа автоматически не импортируются.
Завершите их вручную, сверив оплату, выданные каналы и фактического владельца.

2. Активация
Дождитесь входа Cardinal в нужный FunPay-аккаунт. В личном чате его Telegram-бота
откройте /autochannels либо настройки плагина. Нажмите «Ввести ключ» и отправьте
PLS-… из покупки. Первая успешная проверка привяжет ключ к текущему FunPay ID.
Ключ не нужно вводить повторно после перезапуска. Сервер лицензий получает
только ключ PLS, FunPay ID и код товара. API Hash, SMM-ключ, сессия и 2FA
туда не передаются. Не отправляйте их продавцу или в поддержку.
При временном сбое проверки запас — до 12 часов от последнего успешного
подписанного подтверждения. Блокировка или другой FunPay ID запас не дают.
Кеш успешной проверки — до 60 секунд. Открытый Python не исключает обход.
Смена хостинга с тем же FunPay ID не требует новой покупки; другой FunPay
нужно согласовать через запрос смены в разделе «Лицензии» магазина.

3. Telegram
В настройках укажите API ID и API Hash с my.telegram.org и пароль 2FA
аккаунта продавца. Включите двухшаговую проверку в Telegram заранее.
«Привязать Telegram-аккаунт» выдаст QR: сканируйте его именно рабочим аккаунтом
в Telegram → Настройки → Устройства → Подключить устройство.
Завершите запрос пароля, если он появился. Не рассылайте QR или сессию.
Telegram ограничивает передачу владельца для свежих сессий и недавно
изменённой 2FA; дождитесь разрешения сервиса. Доступность функции зависит
от текущих условий Telegram, прав владельца и приватности покупателя.
Можно выбрать папку, куда будут помещаться создаваемые каналы.

4. SMM-панель и тарифы
Впишите конечный API URL и API-ключ из кабинета своего провайдера, пополните баланс.
Создайте тариф: название, service ID, число подписчиков и целевой запас каналов.
Цена плагина не включает услуги панели. Проверьте, принимает ли услуга
приватные пригласительные ссылки Telegram и какие у неё минимум/максимум.
Качество, сроки и сохранность подписчиков плагином не гарантируются.

5. Привязка FunPay-лота по ID
Создайте предложение в своём кабинете FunPay. Откройте «Лоты → Добавить лот».
Отправьте положительный числовой ID предложения из ссылки offer?id=…
(не ID аккаунта, категории или заказа). Выберите тариф.
Плагин допишет уникальную метку #PLSCH:… в подробное описание лота и проверит,
что FunPay её сохранил. Это реальное изменение описания выбранного предложения.
При невозможности сохранить метку привязка не создаётся.
Не копируйте эту метку в другие лоты. Не удаляйте её; после изменения описания
проверьте или повторите привязку. Старые ключевые слова не используются.
Если полный заказ содержит lot_id/offer_id — проверяется точный ID; если
FunPayAPI его не передаёт — метка берётся из полного оплаченного заказа,
полученного через API продавца. Заголовки и текст чата не используются.

6. Склад и первый заказ
Сначала один небольшой тариф и лот. «Пополнить склад сейчас» создаёт каналы
и отправляет реальные платные запросы SMM-панели. Не нажимайте без готовности
оплатить услугу. Дождитесь статуса готовности и проверьте ссылки/подписчиков.
Проведите один контролируемый заказ FunPay. Количество берётся из полного
заказа (1–50); неизвестное количество не угадывается из названия.
Повторное событие того же заказа не должно повторно резервировать склад.
Если готовых каналов мало, недостающие готовятся отдельно; это не мгновенная
выдача и не гарантия конкретного срока.

7. Передача покупателю
Покупатель получает ссылки и отправляет @username в тот же чат FunPay.
Плагин реагирует только при наличии ожидающих каналов по оплаченному заказу
привязанного лота, от того же buyer ID и с точным совпадением чата.
В посторонних чатах, без ожидающей выдачи, на сообщения продавца и других
ботов ответа нет. Общие FAQ-ответы до оплаты больше не отправляются.
Если ожидают несколько заказов одного покупателя: @username #НОМЕР_ЗАКАЗА.
Перед передачей ещё раз проверяются оплата, покупатель и привязка лота.
Покупателю может понадобиться вступить в канал по ссылке, разрешить добавление
и выполнить требования Telegram для получения владельца.

8. Спорная передача и перезапуск
Начало передачи фиксируется на диске до запроса Telegram. При ошибке или
перезапуске в процессе не повторяйте автоматически: проверьте фактического
владельца каждого канала и запись orders.json. Статус needs_review/transferring
требует ручной сверки продавцом. Смена username после начала передачи
не применяется автоматически. Не удаляйте журнал ради повтора операции.
Новые каналы, зарезервированные перед сбоем, также проверяйте по складу.

9. Обновление и помощь
PLS Store → Лицензии → Скачать — повторная покупка для загрузки не нужна.
Заменяйте файл при остановленном Cardinal, сохраняя сессию и данные.
Для остановки продаж выключите связанные лоты FunPay; остановка Cardinal
сама по себе не скрывает предложения. Лог: storage/plugins/ch_autodeliv_v4.log.
При обращении сообщите версию, номер заказа и обезличенную ошибку;
не присылайте сессию, QR, пароль 2FA или ключи.
