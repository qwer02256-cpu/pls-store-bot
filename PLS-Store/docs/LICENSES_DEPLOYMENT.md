# Лицензии PLS Store: запуск на BotHost

Проверка встроена в тот же aiohttp Application и порт, что `/platega/callback`.
Сервер теперь запускается и без `PLATEGA_CALLBACK_BASE`: опрос Platega продолжает
работать. Отдельный сервер и закрытый ключ подписи не нужны.

## Перед обновлением

1. Сохраните SQLite (`DB_PATH`) и постоянную папку данных. Миграции добавляют
   `licenses`, `license_assets`, `license_audit`, не удаляя товары/покупки.
2. Обновите код из `main`, зависимости остаются прежними. Запуск: `python main.py`
   из `PLS-Store/`. Git push сам по себе не обновляет BotHost.
3. В BotHost подключите публичный HTTPS-домен к существующему HTTP-порту
   `PLATEGA_CALLBACK_PORT` (по умолчанию 8080). Проксируйте также `/licenses/*`,
   если текущая настройка проксирует только `/platega/callback`.
4. Задайте `LICENSE_PUBLIC_BASE=https://публичный-домен` без пути. Если существующий
   `PLATEGA_CALLBACK_BASE` уже является публичным HTTPS origin, он используется
   по умолчанию. Не меняйте действующие реквизиты Platega.
5. Перезапустите приложение. С внешней машины проверьте
   `GET https://домен/licenses/health` → `200 {"ok":true}` и POST на
   `/licenses/verify` с `{}` → 400. Это проверяет доступность маршрута, а не оплату.
   TLS должен быть доверенным для requests на хостинге покупателя.
6. Убедитесь, что SQLite и `data/license_files` лежат на постоянном диске.
   Для загруженных файлов сохраняется абсолютный путь: при смене корня размещения
   загрузите файлы повторно через админку. Встроенный AutoStars использует
   относительный путь к репозиторию.

Локальный тест подтверждает совместную работу маршрутов. Доступность публичного
домена BotHost, его HTTPS и правила reverse proxy нужно подтвердить на самом
хостинге; наличие исходящих платежей/опроса Platega этого не доказывает.
Если тариф BotHost не поддерживает входящий HTTP с публичным HTTPS, онлайн-проверка
в этом приложении на таком тарифе работать не сможет. Не включайте продажи,
пока публичный маршрут не проверен. Код не утверждает обратного.

## Подготовка товара

AutoStars публикуется по утверждённой цене **349 ₽ / навсегда**. При обновлении
существующей базы цена и видимость применяются однократно; последующие ручные
изменения администратора сохраняются. Уже созданные счета сохраняют свою цену.
Новый счёт по-прежнему доступен только при готовых файле, инструкции и HTTPS
адресе проверки. Встроенный файл с защитой и инструкция регистрируются один раз.

Другие товары, в том числе существующий Ch AutoDelivery, не получают файл
AutoStars: для них нужен собственный файл и инструкция. **Новый счёт на товар
без готовых материалов не создаётся.** Старые уже созданные счета продолжают
подтверждаться; лицензия сохранится, выдача ожидает загрузки материалов.
Для исторических завершённых покупок до миграции лицензии автоматически не
создаются: продавец может выдать их вручную, проверив покупку.

Для AutoStars endpoint встраивается при скачивании из текущей переменной
`LICENSE_PUBLIC_BASE`, ключ выдаётся текстом в сообщении бота. После смены домена
старые копии нужно скачать заново; сохраняйте прежний домен работающим на время
перехода. Файл из `plugins/AutoStars.py` в Git содержит шаблон endpoint и не
предназначен для прямой установки без выдачи через магазин.

## Активация AutoStars 2.2

Обновите BotHost, затем скачайте плагин заново через «Лицензии» без повторной
покупки. Остановите Cardinal, замените старый AutoStars.py и уберите дубликаты,
сохранив settings.json. После перезапуска откройте `/autostars`: без ключа
появится активация, при сохранённом ключе он будет проверен перед открытием панели.
Кнопка «Ввести ключ» принимает ключ из магазина и сохраняет только его в
`storage/plugins/AutoStars/license.json` с правами 0600. Команда
`/autostars_license` открывает статус и повторную проверку. Данные Fragment,
seed и кошельки в этот ввод передавать не нужно.

Проверяемая сборка: **v2.2 · PLS-LIC-2.2** в панели/журнале Cardinal. Если её
нет, запущен другой файл. Старую исходную версию без проверки лицензии нельзя
заблокировать через сервер магазина — её нужно заменить выданной версией.
Сохранённый локальный license.json с действующим ключом не требует повторного ручного ввода.
Лицензия привязана к FunPay ID, а не к Telegram-аккаунту покупателя.

Встроенный файл обновляется вместе с кодом, его версия в каталоге — 2.2.
Пользовательские загрузки не заменяются автоматически: если администратор
раньше загрузил свою копию AutoStars, ему нужно обновить её через
`/license_file PRODUCT_ID`. Инструкция обновляется автоматически только при
точном совпадении с прежним встроенным текстом; ручные правки сохраняются.

## Обновление через каталог

В `/admin` → Товары → плагин → **Файл, версия и инструкция** доступны загрузка
нового `.py`, версия и TXT-руководство. См. [подробный порядок обновления](PRODUCT_UPDATES.md).
Выдача: `.py` + ключ сообщением + `INSTALL.txt`. В AutoStars ключ вводится
в панели Cardinal, после чего плагин сам сохраняет локальный `license.json`.

## Администратор

`/admin` → Лицензии показывает справку. Все команды доступны только `ADMIN_ID`.

| Команда | Действие |
|---|---|
| `/license` | Последние 20 лицензий |
| `/license QUERY` | Точный номер лицензии, Telegram ID, FunPay ID или полный ключ |
| `/license_issue TELEGRAM_ID PRODUCT_ID` | Ручная выдача нового ключа, без фиктивного платежа |
| `/license_action ID block` | Заблокировать |
| `/license_action ID unblock` | Разблокировать |
| `/license_action ID reset` | Очистить FunPay ID и запрос смены |
| `/license_file PRODUCT_ID` | Затем отправить `.py` (до 2 МБ) |
| `/license_guide PRODUCT_ID` | Затем текст или UTF-8 `.txt` (до 100 КБ) |
| `/license_log [ID]` | Последние 25 действий, при желании для одной лицензии |
| `/cancel` | Отменить загрузку |

Загружайте для AutoStars файл именно с именем `AutoStars.py` и встроенной
проверкой из этой версии репозитория. Синтаксис проверяется без исполнения.
Файлы доверенного администратора не являются изолированными/проверенными на
вредоносность. Другим плагинам проверку нужно интегрировать отдельно: выдача
лицензии магазином сама по себе не добавляет её проверку в чужой Python.

Покупателю: Профиль → Лицензии или `/licenses`. Список постраничный.
При запросе смены FunPay администратору приходит уведомление; запрос остаётся
в базе, даже если Telegram недоступен. Он виден в `/license`. Сброс выполняется
вручную после проверки запроса. Остановите старую копию перед сбросом: первый
запрос после сброса снова привяжет ключ.

## Гарантии и ограничения

Покупка, бессрочный ключ, журнал и статус платежа фиксируются одной SQLite
транзакцией. `purchase_id UNIQUE` и `BEGIN IMMEDIATE` защищают от повторной и
параллельной выдачи. Только подтверждённый проверенный платёж вызывает выдачу.
Ручная выдача — отдельное явно административное действие; повтор команды
создаёт отдельную лицензию.

После сбоя Telegram повторяется доставка, а не создание лицензии. Отправка
нескольких документов не является транзакцией Telegram: при частичном сбое
покупатель может получить файл повторно с тем же ключом. Фоновая очередь
обходит страницы, чтобы недоступный покупатель не блокировал остальных.

Сервер атомарно привязывает первый FunPay ID, проверяет блокировку и совпадение
ID. Клиент берёт ID из `cardinal.account.id`, проверяет при обработке событий и
перед покупкой Stars. Успешный результат хранится до 60 секунд, ошибки сети
останавливают операции. Уже начатый внешний перевод Stars не отменяется.
FunPay ID сообщает клиент: при изменении открытого Python эту проверку можно
обойти. Криптографическое доказательство аккаунта FunPay здесь не заявляется.

В запрос входят **только key, funpay_id, product**. Seed, токены Fragment,
кошельки и settings.json не передаются серверу лицензий. Исходная интеграция
Fragment остаётся отдельной и использует свой внешний API. Ключ является
секретом доступа; SQLite и резервные копии содержат ключи в открытом виде,
как требуется для повторной выдачи, поэтому доступ к ним должен быть ограничен.
HTTP endpoint принимает ограниченный JSON, не логирует тело и отклоняет
лишние поля; общий лимит процесса — 600 запросов в минуту (429, Retry-After).
На reverse proxy можно настроить дополнительные ограничения. IP не привязан.

## Проверка

Из `PLS-Store/`: `python -m unittest discover -s tests -q`.
Тесты используют временную SQLite и локальный aiohttp, не делают платежей,
не запускают рабочего бота и не переводят Stars. Проверка реального Cardinal
и Fragment на хостинге покупателя остаётся частью пробного запуска по инструкции.
