1. ЧТО ДЕЛАЕТ AUTOSTARS
AutoStars работает внутри FunPay Cardinal. Он принимает информацию о заказах
Telegram Stars, выясняет Telegram username получателя и отправляет Stars через
подключённый Fragment API. В панели продавца настраиваются лоты, доступность
продаж, тексты для покупателей, возвраты, пороги баланса, прокси и статистика.
Сам файл .py не является самостоятельной программой: запускать его командой
python AutoStars.py вместо Cardinal не нужно.

Для работы нужны:
— запущенный FunPay Cardinal, который вошёл в аккаунт продавца FunPay;
— собственный Telegram-бот Cardinal с доступом владельца;
— аккаунт используемого Fragment API и данные для его авторизации;
— кошелёк, поддерживаемый этим API, с достаточным количеством TON;
— ваши лоты Telegram Stars на FunPay;
— исходящий HTTPS и постоянная папка storage на хостинге.
Требуется совместимая версия Python; для этого исходника рекомендуется 3.10+.
Используются зависимости Cardinal, requests и pyTelegramBotAPI (telebot).
Aiogram магазина PLS Store устанавливать вместо telebot в Cardinal не нужно.

Важно различать три системы:
— PLS Store выдаёт плагин, ключ и это руководство;
— FunPay Cardinal принимает заказы и показывает панель /autostars;
— Fragment API авторизует кошелёк и выполняет внешний перевод Stars.
Баланс магазина в рублях не является балансом кошелька TON. Оплата лицензии
не пополняет ваш кошелёк для выдачи Stars покупателям.

2. УСТАНОВКА В CARDINAL
2.1. Остановите Cardinal в панели хостинга.
2.2. Сделайте резервную копию его папки plugins и storage/plugins/AutoStars.
2.3. Поместите выданный AutoStars.py в plugins в корне Cardinal.
Пример расположения:
Cardinal/
  plugins/AutoStars.py
  storage/plugins/AutoStars/settings.json
Не кладите .py в storage/plugins/AutoStars: это папка данных, не загрузки кода.
2.4. Уберите старые копии AutoStars из plugins. Оставлять одновременно старую
и новую версию нельзя: два обработчика могут конфликтовать при работе с заказом.
2.5. Существующий settings.json не удаляйте: там токен, лоты и настройки.
2.6. Запустите Cardinal и проверьте его журнал: не должно быть ошибок импорта.
2.7. В Telegram-боте Cardinal отправьте /autostars. Это команда боту Cardinal,
а не @PLSStore1_bot. Если открылась активация, выполните короткое приложение 18.
2.8. Проверьте версию панели: 2.5.1, метка PLS-LIC-2.5.1.

Для файлового хостинга эти действия выполняются в файловом менеджере панели.
Root-доступ, отдельный VPS и открытие входящего порта у покупателя не нужны.
Каталог storage должен быть подключён к постоянному диску. Если хостинг
удаляет storage при пересоздании контейнера, пропадут токен и все настройки.
После установки отдельно настройте Fragment и лоты — они не создаются
автоматически из факта покупки плагина.

3. КАРТА ПАНЕЛИ
Команда /autostars открывает главное меню.
«Настройки» — переключатели плагина, лотов, возвратов, пороги баланса.
«Лоты» / «Звёзды (лоты)» — количество Stars и ID ваших лотов FunPay.
«Финансы» — расчётная прибыль и цены для расчёта себестоимости.
«Сообщения» — тексты ответов покупателю на разных шагах заказа.
«Лицензия» — статус, замена ключа и повторная проверка; см. приложение 18.
«Инструкция» — короткая встроенная справка; этот TXT содержит полное описание.
В настройках дополнительно находятся «Токен», «Прокси» и «Автоответчик».
«Назад» возвращает на предыдущий уровень, «Домой» — в меню AutoStars.
Если плагин ждёт число или текст, отправьте значение следующим сообщением.
Для отмены ввода используйте /cancel или кнопку отмены в панели Cardinal.

4. ПОДКЛЮЧЕНИЕ FRAGMENT
4.1. Для работы AutoStars необходимо использовать кошелёк Tonhub
с мнемонической фразой из 24 слов. Скачайте Tonhub из официального источника,
создайте отдельный рабочий кошелёк и сохраните его резервную фразу безопасно.
Подключение кошелька с 12 словами не поддерживается. Не дописывайте и не
повторяйте слова, чтобы получить 24; импорт фразы из 12 слов не заменяет
создание подходящего кошелька. Пополняйте новый кошелёк только после проверки
его адреса. Существующие средства не переносятся автоматически.

Сначала проверьте используемого провайдера API. По умолчанию в исходнике
используется https://api.fragment-api.com/v1. Это внешняя интеграция; доступность,
список кошельков, лимиты и правила авторизации определяет этот провайдер.
Не вводите секреты, пока не проверили доверие к нему. Используйте отдельный
кошелёк с минимальным необходимым рабочим балансом.

4.2. Откройте /autostars → Настройки → Токен → Создать токен.
Плагин попросит API-ключ из кабинета провайдера Fragment API. Это не ключ
PLS-… из магазина и не токен Telegram-бота. Получите свой API-ключ в кабинете
провайдера; встроенная справка указывает fragment-api.com/dashboard.

4.3. Следующим сообщением введите телефон в формате, который просит панель:
без знака «+», цифрами. Укажите телефон для вашей авторизации у провайдера.

4.4. Выберите фактическую версию кошелька Tonhub: W5 (V5R1) или V4R2.
Не считайте W5 обязательной только потому, что эта кнопка стоит первой.
Версию нужно узнать в приложении кошелька. Не выбирайте случайную версию:
она должна соответствовать кошельку, с которого планируются переводы.

4.5. На соответствующем шаге AutoStars запрашивает 24 слова мнемоники Tonhub
одной строкой. Эта авторизация относится к внешнему Fragment API, а не к
лицензированию PLS Store. Не присылайте мнемонику в магазин или продавцу.
Плагин пытается удалить сообщение с мнемоникой из чата после получения.
Не отправляйте settings.json или переписку с секретами в общую поддержку.

4.6. После получения 24 слов бот сразу сообщает о подключении к API.
Подключение ограничено 8 секундами, ожидание ответа — 40 секундами.
Если возникает таймаут, сбой прокси, TLS или ошибка соединения, бот сообщает
об этом отдельно. Статус 0 означает отсутствие HTTP-ответа, а не требование
подтвердить вход или доказательство ошибки в мнемонике. Работа сайта с телефона
не проверяет доступность API с хостинга Cardinal. Откройте Настройки → Прокси,
проверьте выбранный режим и соединение. Если у Cardinal настроен рабочий прокси,
можно выбрать режим его использования; иначе требуется исправить доступ
на хостинге. Не отключайте проверку TLS и не повторяйте вход много раз подряд.
После исправления соединения воспользуйтесь кнопкой «Повторить запрос».

Если провайдер запросил подтверждение входа в Telegram, подтвердите его
в своём приложении и воспользуйтесь кнопкой «Я подтвердил вход» в панели.
После ответа доступны кнопки «Я подтвердил вход», «Повторить запрос» и «Отмена».
При ограничении числа попыток дождитесь указанного времени. Частые повторные
запросы не обходят лимит и могут увеличить время ожидания.

4.7. Дождитесь сообщения, что токен создан и привязан. Откройте «Токен» ещё раз:
проверьте состояние токена, версию кошелька и доступный баланс TON.
Если баланс не получен или отображается «—», подключение ещё нельзя считать
проверенным. Сверьте настройки и ответ API в журнале без публикации секретов.

4.8. «Пересоздать токен» повторяет авторизацию, когда старый токен истёк или
нужен другой доступ. «Удалить токен» убирает сохранённую привязку и сведения
о кошельке из настроек плагина. Это не удаляет деньги из самого кошелька.
Перед заменой токена остановите продажи и завершите активные заказы.

4.9. При переходе с версии 2.4 подключение Fragment API Space удалено.
Остановите продажи и сверьте все ранее отправленные запросы, историю TON
и получение Stars ДО замены плагина. Не повторяйте покупки и не возвращайте
деньги вслепую. Новая версия не опрашивает старую очередь. Прежний маркер
подключения сбрасывается; нужно заново создать токен через основной API
с кошельком Tonhub. Другие действующие JWT основного API сохраняются.
Локальные wallet_credentials.json и provider_orders.json не удаляются
обновлением. После сверки сохраните журнал заказов, а файл с seed удалите
с хостинга и из резервных копий, когда он больше не нужен. Удаление файла
не отзывает фразу у сервиса, которому она уже передавалась. Для нового
подключения используйте новый отдельный кошелёк Tonhub.

5. СОЗДАНИЕ И ПРИВЯЗКА ЛОТОВ FUNPAY
5.1. В своём аккаунте FunPay создайте лоты Telegram Stars. Проверьте текст,
цену, единицу товара, количество и то, что продавец — именно ваш аккаунт.
5.2. Обычная категория Stars в исходнике — 2418. Если FunPay изменил каталог,
проверьте актуальную категорию и переменную AUTOSTARS_CATEGORY_ID у хостинга.
Не путайте ID категории, ID аккаунта и LOT_ID — это три разных номера.
5.3. Для каждого лота получите его числовой LOT_ID. Используйте номер именно
лота из кабинета/ссылки редактирования FunPay, а не номер заказа покупателя.
При сомнении сверьте ID в кабинете FunPay или журнале Cardinal.
5.4. Откройте /autostars → Лоты → Добавить лот.
5.5. Сначала введите количество Stars для этого предложения. Допустимый ввод
в текущей версии — целое число от 50 до 1 000 000. Например: 50.
5.6. Затем отправьте положительный числовой LOT_ID. Например: 12345678.
Это только пример; в реальной настройке нужен ID вашего лота.
5.7. Проверьте строку в списке: 50⭐ → LOT 12345678. Добавление помечает лот
активным и пытается включить его на FunPay. Готовьте кошелёк до этого шага
или временно держите плагин выключенным и лоты недоступными для покупок.
5.8. Повторите для остальных предложений: 100, 333, 1000 Stars и т. д.
Повторное добавление того же LOT_ID обновляет его количество, а не создаёт
отдельную запись для другого предложения.
5.9. Нажатие на строку лота переключает его активность. Кнопки «Включить все»
и «Выключить все» применяют действие к сохранённым лотам.
5.10. Кнопка удаления убирает связку из списка плагина; это не удаление самого
предложения из аккаунта FunPay. Состояние предложения проверяйте отдельно.

6. ПЛАГИН И ЛОТЫ: ДВА РАЗНЫХ ПЕРЕКЛЮЧАТЕЛЯ
«Плагин» разрешает или останавливает работу обработчиков AutoStars.
«Лоты» управляет доступностью предложений на FunPay.
Перед включением лотов плагин должен быть включён. Если список своих лотов
задан, переключатель работает с ним. Если список пуст, исходная логика может
переключать предложения всей заданной категории — для точного управления
сначала добавьте конкретные LOT_ID.
Выключение плагина само по себе не следует считать подтверждённым скрытием
всех предложений на FunPay. При остановке продаж выключите лоты и проверьте
их реальное состояние в кабинете FunPay, затем отключите обработку плагина.
Переключатели не отменяют уже начатый внешний перевод Stars.

7. КАК ПРОХОДИТ ЗАКАЗ
После оплаченного заказа плагин проверяет, относится ли заказ к Stars,
определяет количество и добавляет его в очередь соответствующего чата.
Покупатель получает просьбу прислать Telegram username получателя.
Нужен @username, например @sample_user: латинские буквы, цифры и подчёркивания,
длина 5–32 символа. Отображаемое имя, телефон и числовой Telegram ID не подходят.

Если корректный username уже пришёл вместе с событием нового заказа и токен
доступен, исходный обработчик может начать отправку сразу, без отдельного «+».
Не размещайте случайный @username в данных заказа и заранее проверьте этот
сценарий. Отдельное подтверждение относится к диалогу запроса имени ниже.
Количество определяется из доступного заголовка/системного сообщения заказа.
Указывайте Stars однозначно и проверяйте фактическое количество при тесте;
не рассчитывайте на неподтверждённое автоматическое умножение по order.amount.

Плагин проверяет формат и существование username через Fragment API.
При неправильном имени покупатель должен прислать исправленный тег.
После принятия имени покупатель видит количество и получателя. В текущей
переписке подтверждение отправки запрашивается сообщением «+». Пока заказ
ожидает подтверждения, можно прислать другой @username для исправления.
Не подтверждайте выдачу на неверного получателя: выполненный перевод Stars
не отменяется редактированием сообщения или последующим сбросом лицензии.

После подтверждения плагин повторно проверяет доступ, выполняет отправку
через Fragment API и пишет результат. При успехе выводятся сообщение об
отправленных Stars и ссылка на заказ FunPay, если известен его номер.
Отправка происходит с show_sender=False в текущем исходнике.
Если в чате есть несколько покупок, используется очередь: после успешной
выдачи плагин переходит к следующему заказу и снова запрашивает username.
Очередь хранится в памяти процесса. Не перезапускайте Cardinal посреди
неразобранных заказов без сверки с журналом заказов FunPay и фактом переводов.
Наличие сообщения «Отправляю» ещё не является доказательством перевода:
проверьте итоговый ответ и фактическое получение Stars.

8. ВОЗВРАТЫ: АВТОМАТИЧЕСКИЙ И !БЭК
По умолчанию автовозврат выключен, команда !бэк выключена.
В /autostars → Настройки есть отдельные переключатели для каждой функции.

Автовозврат: если отправка завершилась ошибкой и известен номер заказа,
плагин пытается вызвать возврат средств через аккаунт FunPay Cardinal.
Если функция выключена, покупатель получает просьбу дождаться продавца.
«Пытаюсь оформить возврат» означает попытку, а не подтверждение возврата.
Проверяйте итоговый статус в FunPay. Сетевой таймаут может оставить неясным,
прошёл ли перевод Stars; перед повторной отправкой/возвратом сверяйте факт
операции, чтобы не отправить Stars повторно и не вернуть деньги за выдачу.

!бэк: ручной запрос покупателя до завершённой выдачи, если продавец разрешил
эту команду. При нескольких ожидающих заказах указывайте нужный номер:
!бэк НОМЕР_ЗАКАЗА. Проверяйте, что заказ ещё ожидает username/подтверждение.
Подтверждённые и завершённые выдачи не являются свободно отменяемыми заказами.
Приоритет !бэк: «выше/ниже автовозврата» задаёт порядок обработки ручного
запроса относительно автоматического сценария. Это не приоритет в сети TON
и не обещание отменить уже начатый перевод. Если приоритет !бэк установлен
ниже автовозврата, а сам автовозврат выключен, текущий код отклоняет !бэк.
Для отдельного ручного возврата включите !бэк и выберите высокий приоритет.

9. ЗАЩИТА ПО ОСТАТКУ TON
В настройках задаются два разных порога.
«Порог автодеактивации» — при каком остатке отключать лоты, если включена
автодеактивация. По умолчанию используется 5 TON (или AUTOSTARS_MIN_BALANCE_TON).
«Порог уведомлений» — при каком остатке уведомлять продавца; по умолчанию 10 TON.
Автоотключение в исходнике затрагивает предложения всей заданной категории,
а не только сохранённые пары LOT_ID. Учитывайте другие ваши лоты Stars.
Это числовые значения в TON, не рубли и не количество звёзд.
Для ввода допустимо неотрицательное число, например 5 или 4,2.
Ноль в пороге автодеактивации не является способом выключить защиту: текущий
код подставляет стандартный порог. Для отключения используйте переключатель.

Пример: уведомления — 10 TON, отключение — 5 TON. Сначала продавец получает
сигнал пополнить кошелёк, затем при дальнейшем снижении плагин выключает лоты.
Проверка баланса вызывается рабочими обработчиками, в частности после попыток
выдачи. Это не отдельный непрерывный мониторинг каждую секунду. Не считайте
порог гарантией наличия средств для любого размера следующего заказа.
Рассчитайте запас под самый большой лот и возможную очередь заказов.
После пополнения проверьте новый доступный баланс и вручную убедитесь, что
нужные лоты снова включены. Не обещайте покупателям выдачу до этой проверки.

10. ФИНАНСЫ И РАСЧЁТ ПРИБЫЛИ
Откройте /autostars → Финансы.
«Изменить цену 1 TON (₽)» — ваш рублёвый курс покупки TON.
«Изменить цену 50⭐ (TON)» — расход TON на 50 Stars по вашим условиям API.
Исходные значения 125 ₽ и 0,115 TON являются примерами настроек, не актуальными
рыночными котировками. Введите реальные значения до начала продаж.

Расчёт:
расход TON = количество Stars / 50 × цена 50 Stars в TON;
себестоимость ₽ = расход TON × ваш курс TON;
прибыль ₽ = выручка по заказу FunPay − расчётная себестоимость ₽.
Например: 100 Stars, 0,115 TON за 50 Stars, курс 125 ₽ за TON.
Расход = 0,23 TON; себестоимость = 28,75 ₽. Если цена заказа 40 ₽,
расчётная прибыль составит 11,25 ₽.

Выручка берётся из доступных данных заказа FunPay. Если запрос заказа не удался,
статистика может не получить выручку. Отдельные комиссии сети, провайдера,
конвертации и вывода не следует считать автоматически полностью учтёнными.
Это расчётная статистика плагина, а не выписка вашего кошелька или бухгалтерия.
Параметры фиксируются при записи конкретной продажи: смена курса влияет на
следующие записи и не пересчитывает предыдущие операции автоматически.
В панели выводятся показатели за текущую дату по времени сервера Cardinal.
Изменение этих параметров не меняет цену самого лота на FunPay — её нужно
редактировать отдельно в кабинете FunPay.

11. ШАБЛОНЫ СООБЩЕНИЙ ПОКУПАТЕЛЮ
Откройте /autostars → Сообщения.
Выберите этап и нажмите кнопку редактирования, затем отправьте новый текст.
Кнопка сброса возле шаблона возвращает стандартный текст.

Этапы:
purchase_created — заказ принят, нужно запросить username;
username_received — тег получен и проверяется;
username_invalid — тег неверный или не найден;
username_valid — получатель и количество приняты;
sending — начинается попытка отправки;
sent — успешная выдача;
failed — ошибка отправки.

Подстановки пишутся в фигурных скобках точно как в примерах:
{qty} — количество Stars;
{username} — Telegram username получателя;
{order_id} — номер заказа, когда он доступен на данном этапе;
{order_url} — ссылка на заказ;
{reason} — описание ошибки для failed.
Подставляются только данные, переданные конкретному этапу. Не используйте
{reason} в приветствии и не рассчитывайте на {order_url} до появления заказа.
При неверном названии переменной форматирование может не выполниться, и
покупатель увидит фигурные скобки буквально.

Пример purchase_created:
Спасибо за покупку {qty}⭐! Пришлите Telegram username получателя: @username.
Пример sent:
Готово: {qty}⭐ отправлены на @{username}. Заказ: {order_url}
Пример failed:
Не удалось отправить Stars: {reason}. Дождитесь продавца.

Сохраняйте в сообщениях понятную просьбу прислать username и порядок
подтверждения. Меняйте только шаблоны уведомлений, не обещайте неподдерживаемые
команды. После правок сделайте тестовый заказ и посмотрите реальные ответы.

12. ПРЕДПРОДАЖНЫЙ АВТООТВЕТЧИК
В настройках откройте «Автоответчик (Пре-сейл)».
Включите функцию и задайте текст ответа. По умолчанию она выключена.
Она отвечает на короткие типовые вопросы покупателя, пришедшего с лота Stars:
например, «Тут?», «Работаешь?», «Автовыдача?». Это не универсальный ИИ-оператор
и не обработчик всех возможных вопросов. Логику распознавания задаёт исходник.
Текст должен соответствовать вашему фактическому режиму: если кошелёк не
пополнен или лоты выключены, не обещайте гарантированную выдачу 24/7.
Изменение текста автоответчика не меняет шаблоны выдачи из раздела «Сообщения».
Проверьте его отдельным вопросом с тестового аккаунта до обычных продаж.

13. ПРОКСИ И СЕТЕВОЕ ПОДКЛЮЧЕНИЕ
/autostars → Настройки → Прокси.
Режимы: выключен; от Cardinal; свой прокси. Переключатель циклически меняет режим.
«От Cardinal» использует доступный прокси из настроек самого Cardinal/аккаунта.
«Свой» требует ввести адрес в отдельном поле:
http://host:port
или http://user:password@host:port
Используйте адрес своего провайдера; примеры не являются рабочими прокси.
«Проверить соединение» выполняет сетевую проверку и показывает внешний IP
и HTTP-ответ Fragment API. Ответ сам по себе не доказывает успешную авторизацию
кошелька: отдельно проверяйте токен и доступный баланс.

Прокси применяется к запросам Fragment в соответствии с настройками плагина.
Он не отменяет лимиты API и не гарантирует устранение HTTP 429.
При 429 дождитесь разрешённого интервала и проверьте ограничения провайдера.
Лицензирование использует обычный requests и системные HTTP_PROXY/HTTPS_PROXY,
а не секретный словарь прокси Fragment. На хостинге должен быть разрешён
исходящий HTTPS и к Fragment API, и к домену проверки лицензий магазина.
При ошибках TLS проверьте дату системы и доверенные сертификаты хостинга.
Не отключайте проверку сертификатов для обхода ошибки.

14. ПЕРВЫЙ ПРОВЕРОЧНЫЙ ЗАКАЗ
Перед тестом:
— Cardinal вошёл в нужный FunPay, в журнале нет ошибок импорта;
— панель /autostars открывается и лицензия подтверждена;
— токен Fragment создан, баланс читается;
— реальные параметры финансов внесены;
— один тестовый лот сопоставлен с нужным LOT_ID и количеством;
— остальные лоты временно недоступны, автоматические возвраты пока выключены.

Оформите небольшой контролируемый заказ на тестовом лоте. Оплата такого заказа
и перевод Stars являются реальными внешними операциями.
1) Проверьте получение просьбы прислать username.
2) Пришлите заведомо неправильный формат, например пробелы вместо @username.
   Убедитесь, что отправка не началась и плагин просит исправить имя.
3) Пришлите корректный username выбранного получателя.
4) Сверьте количество и имя в запросе подтверждения.
5) Подтвердите отправку символом «+», если именно это запрошено сообщением.
6) Дождитесь итогового ответа и проверьте фактическое поступление Stars.
7) Сверьте номер заказа, журнал Cardinal и запись в финансах.
8) При наличии второго заказа проверьте переход очереди к следующему.
После успешного теста настройте нужные правила возврата, включите оставшиеся
лоты и ещё раз проверьте их видимость и цены в FunPay.

15. ПОВСЕДНЕВНАЯ РАБОТА
Перед началом дня проверьте доступность Cardinal, токен и достаточный TON.
Сверяйте лоты и цену, если изменился курс или условия Fragment API.
Следите за уведомлениями и не ждите полного исчерпания кошелька.
Периодически сохраняйте резервную копию storage/plugins/AutoStars.
Перед обслуживанием выключите лоты, проверьте незавершённые заказы и только
затем останавливайте Cardinal. После запуска сверяйте неразобранные заказы
в FunPay: очередь плагина хранится в памяти, а не является заменой истории FunPay.

16. ОБНОВЛЕНИЕ И ПЕРЕНОС
В PLS Store откройте главное меню → Лицензии → нужная лицензия → Скачать.
Повторная покупка не нужна: выдаются текущий файл и инструкция, ключ сохраняется.
Остановите Cardinal, сделайте резервную копию, замените plugins/AutoStars.py,
сохраните settings.json и существующий локальный license.json. Уберите старые
копии .py. Запустите Cardinal и выполните один проверочный заказ.
Новый файл не устанавливается в Cardinal автоматически при обновлении магазина.

При смене хостинга перенесите plugin и папку storage/plugins/AutoStars.
Если аккаунт FunPay тот же, сброс привязки не требуется: IP и железо не привязаны.
При смене FunPay остановите старую копию, запросите смену в магазине и дождитесь
сброса продавцом. Затем запускайте плагин на нужном аккаунте. Первый успешный
запрос после сброса заново привязывает ключ; старая работающая копия может
успеть привязать его обратно, поэтому её нужно остановить заранее.

17. ЧАСТЫЕ ОШИБКИ
Нет /autostars: проверьте папку plugins, отсутствие дубликатов .py, зависимости,
журнал загрузки Cardinal и доступ владельца к его Telegram-боту.
Токен не создан: проверьте API-ключ, телефон, версию кошелька, ответы провайдера,
подтверждение Telegram и лимиты попыток. Не путайте токен Fragment с ключом PLS.
Баланс «—»: ответ кошелька не получен; проверить сеть, авторизацию и провайдера.
Нет реакции на заказ: сверить, включён ли плагин, категорию и принадлежность лота,
вошёл ли Cardinal в FunPay, есть ли токен и нет ли ошибки лицензии в журнале.
Не принимает username: нужен публичный Telegram username, 5–32 символа,
латиница/цифры/подчёркивания. Убедитесь, что аккаунт существует и API его видит.
«Отправляю» без результата: не повторяйте перевод вслепую. Сначала сверяйте
факт операции и ответ внешнего API, затем решайте, нужна ли повторная попытка.
Лоты сами выключились: проверить доступный TON, порог и причину деактивации.
Лоты не выключились: проверить настройки автоотключения, данные баланса и
выполнение обработчика; дополнительно скрыть предложения вручную в FunPay.
Не работает !бэк: проверить переключатель, номер и этап конкретного заказа.
Прибыль неверная: проверить курс TON, стоимость 50 Stars, доступность цены заказа
и неучтённые комиссии; старые записи не пересчитываются сменой параметров.
Исчезли настройки после рестарта: настроить постоянное хранение папки storage.
Ошибка лицензии: короткая проверка в приложении 18. Переустановка токена Fragment
не снимает блокировку лицензии и не меняет её FunPay ID.
Поддержке сообщайте номер лицензии, версии Python/Cardinal/плагина, хостинг,
номер заказа и текст ошибки без JWT, seed, полного ключа и данных кошелька.

18. КОРОТКО ОБ АКТИВАЦИИ
В комплекте два файла: AutoStars.py и INSTALL.txt.
Ключ приходит отдельным текстом в сообщении бота. Скопируйте строку PLS-…
из сообщения о покупке или из раздела «Лицензии» целиком.
В Telegram-боте Cardinal: /autostars → Ввести ключ → отправьте эту строку.
Плагин сохранит её локально в storage/plugins/AutoStars/license.json.
Повторный ввод при каждом запуске не нужен. Статус: /autostars_license.
Альтернатива для ручной установки: создать license.json с содержимым
{"key": "PLS-ваш-полный-ключ"}. Это не settings.json и не файл токена Fragment.

Лицензия бессрочная для одного FunPay ID. Проверка отправляет только ключ,
FunPay ID и обозначение продукта autostars; данные Fragment, кошелька и seed
серверу лицензий не передаются. Нужен HTTPS-доступ к магазину для первой
активации и периодических проверок. Успешная проверка даёт подписанное
подтверждение на 12 часов от момента её выполнения. Подтверждение сохраняется
в storage/plugins/AutoStars/license_status.json и переживает перезапуск Cardinal.
При обычной работе сервер перепроверяется примерно раз в 60 секунд перед
защищёнными операциями. При сбое сети/сервера плагин временно работает по
последнему подтверждению, не дольше 12 часов от последнего успешного ответа.
Сетевые ошибки не продлевают этот срок. После истечения работа останавливается
до успешной онлайн-проверки. На странице «Лицензия» видны временный режим и
оставшееся время. Если сервер вернул блокировку, неверный ключ или другой
FunPay ID, подтверждение аннулируется, льготный период не используется.
Первый запуск, новый ключ и новый FunPay ID требуют онлайн-проверки. Кеш должен
быть доступен для записи; не удаляйте его при обычном перезапуске. Часы хостинга
должны быть настроены правильно. Лицензия не привязана к IP/железу.
Если связи нет, новая блокировка может стать известна только при восстановлении
связи или по окончании 12 часов. Уже начатый перевод отменить проверкой нельзя.
Открытый Python и локальные файлы можно менять/восстанавливать; абсолютная
защита от обхода или подмены системного времени не обещается.
