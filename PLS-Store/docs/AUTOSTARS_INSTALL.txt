PLS STORE / AUTOSTARS 2.1 — ПОДРОБНАЯ ИНСТРУКЦИЯ

1. КОМПЛЕКТ И УСЛОВИЯ
AutoStars.py — плагин для FunPay Cardinal. license.json — персональный ключ.
Лицензия бессрочная, на один аккаунт FunPay, без даты окончания. Она может
быть заблокирована продавцом. Для работы нужна связь с магазином по HTTPS.
Ключ не меняется при повторном скачивании. Не публикуйте ключ и license.json.
В магазине: Профиль → Лицензии → номер лицензии. Здесь доступны статус,
FunPay ID, файл, инструкция и запрос смены аккаунта. При ошибке доставки
покупка сохраняется, магазин повторит отправку. Можно скачать вручную.

2. ПОДГОТОВКА ХОСТИНГА
Нужен работающий FunPay Cardinal с входом в ваш FunPay и настроенным
Telegram-ботом Cardinal. Обычный Telegram-бот не заменяет Cardinal.
Сделайте резервную копию Cardinal и папки storage/plugins/AutoStars.
У хостинга должны быть разрешены свои плагины .py, запись в storage/plugins
и исходящие HTTPS-запросы. Отдельный VPS, входящий порт у покупателя,
Docker или привязка к IP не требуются. Рекомендуется Python 3.10+.
Исходный плагин использует requests, pyTelegramBotAPI (telebot) и FunPayAPI
из окружения Cardinal. Если модуль отсутствует, установите зависимости
через панель хостинга по инструкции Cardinal. Aiogram здесь не замена telebot.
Папка storage должна сохраняться при перезапусках и пересоздании контейнера.

3. УСТАНОВКА ПО ШАГАМ
а) Остановите Cardinal в панели хостинга.
б) Сохраните старый файл AutoStars и настройки в резервную копию.
в) Поместите выданный AutoStars.py в plugins в корне Cardinal, рядом с другими
плагинами .py. Уберите дубликаты старых версий. Не кладите .py в storage.
г) Создайте storage/plugins/AutoStars, если её нет.
д) Положите выданный license.json в storage/plugins/AutoStars/license.json.
Это отдельный файл, не settings.json. При ручном создании:
{"key": "PLS-ваш-полный-ключ"}
Используйте UTF-8, обычные двойные кавычки. Расширение .json, не .json.txt.
е) Не заменяйте settings.json: в нём настройки Fragment, лотов и сообщений.
ж) Запустите Cardinal. Дождитесь успешного входа в FunPay.
з) В Telegram-боте Cardinal откройте /autostars или настройки плагина.
На файловых хостингах те же действия выполняются через файловый менеджер
панели; установка системного сервиса и root-доступ не нужны.

4. АКТИВАЦИЯ И СМЕНА ПРИВЯЗКИ
Плагин получает реальный числовой ID из cardinal.account.id. Это ID FunPay,
не Telegram ID, не username и не ID лота. Первый успешный запрос связывает
ключ с этим аккаунтом. Проверка вызывается при событиях сообщений/заказов
и перед отправкой Stars. Просто открытие панели может ещё не привязать ключ.
Посмотрите FunPay ID в «Лицензии» после первого события.
Не тестируйте лицензию на чужом аккаунте: он станет первой привязкой.
При переносе хостинга с тем же FunPay просто перенесите plugin, license.json
и настройки. IP и оборудование не привязаны.
При смене FunPay: остановите старую копию, запросите смену через магазин,
дождитесь решения администратора и сброса, запустите новую копию на нужном
FunPay. Первый запрос после сброса привязывает заново. Сам запрос не сбрасывает
аккаунт. Если старая копия продолжает работать, она может привязать ключ снова.

5. КАК РАБОТАЕТ ПРОВЕРКА
К магазину уходят только ключ, FunPay ID и строка продукта autostars.
Токены Fragment, мнемоника/seed, данные кошелька, пароль FunPay, Telegram-токен
и settings.json в проверку лицензии не включаются.
Проверка идёт по HTTPS с проверкой сертификата, без перехода по редиректам.
При недоступности сети или сервера, неверном ключе, блокировке или другом
FunPay отправка Stars останавливается. Не отключайте TLS для устранения ошибок.
Успешная проверка хранится в памяти до 60 секунд только для текущего FunPay ID.
Блокировка действует при следующей проверке перед защищённой операцией,
после истечения этого интервала. Уже начатый внешний перевод не отменяется.
Бессрочность не означает работу офлайн. Открытый Python допускает изменение
кода; абсолютная защита от обхода не обещается.

6. НАСТРОЙКА FRAGMENT
В /autostars откройте настройки/токен. Исходный AutoStars использует внешний
Fragment API. Авторизация может запросить API-ключ, телефон, версию кошелька
и мнемонику; это исходная функция плагина, отдельная от лицензирования.
До ввода секретов проверьте доверие к используемому провайдеру Fragment API.
Используйте выделенный кошелёк с минимально необходимым балансом.
Ничего из этих реквизитов не вводите в PLS Store и не пересылайте продавцу.
Следуйте шагам панели: ввод данных → выбор версии кошелька → подтверждение.
Убедитесь, что панель показывает привязанный токен и нужный кошелёк/баланс.
Ошибки внешнего API, изменённые endpoints и нехватка TON не исправляются
сменой лицензии. Не повторяйте платёж Stars вслепую после сетевого таймаута:
сначала проверьте, состоялась ли отправка.

7. ЛОТЫ, ПРОДАЖИ И ОГРАНИЧЕНИЯ
В разделе Stars добавьте ваши лоты с числовыми ID и количеством звёзд.
Проверьте владельца лотов и соответствие количества описанию товара.
Стандартная категория исходного плагина — 2418. При изменении каталога FunPay
укажите актуальную AUTOSTARS_CATEGORY_ID в переменных среды Cardinal.
ID категории, аккаунта и лота — разные значения.
В панели настройте цену, минимальный баланс TON, уведомления, автоотключение
лотов при недостатке средств, автовозврат, подтверждение отправки, приоритет
обработки и тексты сообщений. До включения автоматических возвратов проверьте
на тестовом заказе условия возврата. Проверьте, что покупатель передаёт
правильный Telegram username получателя, а не телефон или отображаемое имя.
В настройках сообщений можно изменить шаблоны запросов и ответы покупателю.
Предпродажные ответы включайте после проверки текста и соответствия лотам.
Не включайте обычные продажи, пока Fragment не авторизован и баланс не проверен.

8. ПРОКСИ И СЕТЬ
Прокси Fragment настраивается в панели AutoStars. Лицензирование использует
обычный requests и системные переменные HTTPS_PROXY/HTTP_PROXY, а не секретную
конфигурацию Fragment. Разрешите исходящий HTTPS к домену магазина из
выданного AutoStars.py. Не подменяйте URL лицензий адресом Fragment API.
При TLS-ошибке проверьте дату системы и сертификаты хостинга. При блокировке
домена обратитесь к хостингу. Не отключайте проверку сертификатов.

9. ПРОВЕРОЧНЫЙ ЗАКАЗ
Проверьте статус лицензии в магазине, работу панели и отсутствие ошибок
импорта в журнале Cardinal. Включите плагин, проверьте лоты и баланс.
Проведите один небольшой контролируемый заказ. Проверьте распознавание лота,
количество, запрос username, подтверждение, фактическое получение Stars и
завершение заказа. Проверьте реакцию на неправильный username. Только затем
запускайте регулярные продажи. Сохраните резервную копию рабочих настроек.

10. ДИАГНОСТИКА
«FunPay ID ещё недоступен»: дождитесь входа Cardinal; проверьте авторизацию
FunPay и версию Cardinal. Проверке нужен cardinal.account.id.
«Лицензия не подтверждена»: проверьте путь license.json, полный ключ, статус
в магазине, FunPay ID и HTTPS-доступ. После исправления повторите событие или
перезапустите Cardinal. При блокировке обратитесь в поддержку магазина.
Нет /autostars: проверьте папку plugins, дубликаты, зависимости и логи импорта.
Нет лотов: проверьте аккаунт, ID и категорию. Не используйте чужие ID.
Fragment не авторизуется: проверьте настройки и ответ Fragment API, лимиты
и баланс. Лицензионный сервер этими операциями не управляет.
После рестарта пропали ключ/настройки: подключите постоянный диск storage.
Не скачивается файл: проверьте статус и поддержку; ключ и покупка сохраняются.

11. ОБНОВЛЕНИЕ И ПОДДЕРЖКА
Остановите Cardinal, сохраните копию, скачайте свежий файл в «Лицензии»,
замените .py и сохраните license.json/settings.json. Запустите Cardinal,
проверьте журнал и тестовый заказ. Инструкцию можно скачать отдельно.
Поддержке сообщайте номер лицензии, FunPay ID, версии Python и Cardinal,
хостинг и текст ошибки без секретов. Не отправляйте seed, JWT, полный ключ,
settings.json или полные логи с реквизитами в публичные чаты.
