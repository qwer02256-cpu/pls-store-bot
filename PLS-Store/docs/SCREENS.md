# Переходы без эффекта удаления

Обычная навигация меняет текст, подпись к баннеру и кнопки в текущем сообщении
через методы редактирования Telegram. `deleteMessage` не вызывается. Анимацию
удаления задаёт клиент Telegram; отдельного параметра отключения у бота нет.
Введённые команды остаются в чате. Каждая команда (`/start`, `/profile`,
`/license` и т. п., включая команды с @именем бота) получает ответ новым
сообщением. Это сообщение становится текущим экраном: последующие нажатия
кнопок редактируют его. Со старого экрана снимаются кнопки, сам он сохраняется
без эффекта удаления. Обычный ввод данных в пошаговом диалоге продолжает
обновлять текущий экран.

Короткие экраны с баннером используют подпись фотографии. Баннер сохраняется
при переходе в текстовый раздел. Для длинного текста (более 1024 символов)
один раз добавляется отдельное текстовое сообщение; затем эта пара сообщений
переиспользуется и на коротких экранах. Это обходит ограничение подписи без
удаления баннера или старого текста. Пара сохраняется в `chat_screens` вместе
с типом сообщения и продолжает работать после перезапуска.

Если Telegram окончательно запрещает редактировать старый экран, бот отправляет
новый и снимает кнопки со старого, также без удаления. При ошибке сети бот
сохраняет текущий экран. Старая история не сканируется: Telegram Bot API не
предоставляет метод чтения истории чата. Документы плагина и инструкции остаются
доступны. Кнопки оплаты и повторной проверки счёта сохраняются при просмотре
статуса платежа. Переход «Назад» отменяет незавершённый ввод.

В `/admin` → Лицензии есть карточки с кнопками блокировки, разблокировки,
сброса FunPay и журнала. Сброс через кнопку требует подтверждения. Список
сначала показывает лицензии с запросами смены привязки.

Команда `/license_action 1 reset` сбрасывает лицензию **№1**. Её аргумент —
номер лицензии, а не FunPay ID или Telegram ID. Поиск по FunPay ID:
`/license FUNPAY_ID`; затем выберите найденную карточку.

Для запуска обновите `main` и перезапустите магазин на BotHost. Новых переменных
не требуется. Миграция добавляет поле `kind` в существующую таблицу экранов.
