# PLS Store

Telegram-магазин цифровых товаров на **aiogram 3** + **SQLite** + **Platega**.

[![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/downloads/)
[![aiogram 3](https://img.shields.io/badge/aiogram-3.x-blue.svg)](https://docs.aiogram.dev/)

## Возможности

- 🛒 Каталог товаров с карточками, фото, описанием, статьёй и видео
- 💳 **Platega** — пополнение внутреннего баланса (СБП / карты)
- 👤 Профиль: баланс, потрачено, покупки, рефералы
- 🛒 Покупка с баланса (автоматическая) + ручные заявки
- 🔗 Реферальная система (% от пополнений)
- 🎟 Промокоды
- ❓ FAQ с краткими ответами и отдельной страницей «📄 Документы» (политика конфиденциальности, пользовательское соглашение, товары и тарифы)
- 🎨 Полностью настраиваемые тексты кнопок и разделов через админку
- 🖼 Баннеры для главного меню, профиля, магазина, FAQ, пополнения
- 🛠 Админ-панель: товары, заявки, платежи, пользователи, балансы, покупки, промо, FAQ, дизайн

## Быстрый старт

```bash
git clone https://github.com/YOUR_USER/PLS-Store.git
cd PLS-Store
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
# заполните .env
python main.py
```

## Переменные окружения

| Переменная | Описание |
|------------|----------|
| `BOT_TOKEN` | Токен бота от @BotFather |
| `ADMIN_ID` | Ваш Telegram user ID |
| `SUPPORT_USERNAME` | Username поддержки (без @) |
| `REVIEWS_URL` | Ссылка на отзывы |
| `DB_PATH` | Путь к SQLite (по умолчанию `data/store.db`) |
| `PLATEGA_MERCHANT_ID` | UUID мерчанта из кабинета Platega |
| `PLATEGA_SECRET` | Секретный ключ Platega |
| `PLATEGA_CALLBACK_BASE` | Публичный HTTPS URL (например `https://bot.example.com`) |
| `PLATEGA_CALLBACK_PORT` | Порт локального HTTP-сервера колбэков (по умолчанию `8080`) |

См. `.env.example`.

## Platega

1. Получите `MerchantId` и `Secret` в [кабинете Platega](https://platega.io).
2. Укажите Callback URL:
   ```
   https://ваш-домен/platega/callback
   ```
3. Бот поднимает aiohttp-сервер на `PLATEGA_CALLBACK_PORT` и принимает POST с заголовками `X-MerchantId` / `X-Secret`.
4. При статусе `CONFIRMED` сумма идемпотентно зачисляется на баланс пользователя.

Официальная документация: https://docs.platega.io/

## FAQ и документы

В пользовательском разделе FAQ показываются краткие ответы и кнопка «📄 Документы». На странице документов размещены внешние статьи:
- Политика конфиденциальности
- Пользовательское соглашение
- Товары и тарифы

Ссылки открываются непосредственно через URL-кнопки Telegram.

## Админ-команды

| Команда | Описание |
|---------|----------|
| `/admin` | Панель управления |
| `/addpromo CODE 100 [лимит]` | Создать промокод на сумму |

В `/admin` доступны:
- Товары (создание, редактирование, скрытие)

### Premium Emoji в кнопках

Для Premium Emoji в кнопках требуется aiogram 3.25.0 или новее и Telegram Bot API 9.4+.
Откройте `Админ-панель → Дизайн → нужная кнопка` и отправьте сообщение с Premium Emoji
(можно вместе с текстом). Бот сохранит ID эмодзи отдельно и передаст его в поле
`icon_custom_emoji_id`, чтобы Telegram показывал эмодзи как иконку слева от текста кнопки.
Владелец бота должен иметь Telegram Premium (либо бот должен соответствовать условию
с дополнительными именами пользователя, приобретёнными через Fragment).

## Языки интерфейса

В главном меню добавлен выбор языка: русский и English. Выбор сохраняется отдельно для каждого Telegram-пользователя в SQLite; новые пользователи получают русский язык по умолчанию. Переключение применяется сразу, без перезапуска бота. Для существующей базы данных поле `users.language` добавляется автоматически при запуске.

## Команда администратора

Команда `/admin` отображается только в списке команд Telegram для ID, указанного в `ADMIN_ID`. Обычным пользователям показываются только публичные команды. Административные команды и обработчики дополнительно проверяют Telegram ID на сервере; скрытие команды в интерфейсе не является единственной защитой.

## Анимированные эмодзи PLS Store

При запуске бот получает `custom_emoji_id` из опубликованного набора
`https://t.me/addemoji/PLSstoreemoje`. Цветные флаги дополнительно загружаются
из `https://t.me/addemoji/PLSStoreFlags` с приоритетом над флагами основного
набора. Флаги с `needs_repainting=true` пропускаются, чтобы они не превращались
в одноцветные прямоугольники. Совпадающие обычные эмодзи заменяются
в HTML-сообщениях, подписях баннеров и иконках inline-кнопок.
ID сохраняются в SQLite; при временной недоступности набора используются
сохранённые значения, а при первом запуске — обычные эмодзи.

После добавления новых эмодзи в набор администратор может отправить
`/syncemojis`, затем открыть меню заново. Старые сообщения автоматически
не обновляются. Для другого набора или нескольких наборов задайте
`CUSTOM_EMOJI_PACKS` (имена или ссылки через запятую). Сопоставление идёт
по обычному эмодзи, назначенному при загрузке в @Stickers.

Проверка модуля: из `PLS-Store` запустите
`python -m unittest discover -s tests -v`.

## Настройка оплаты Platega на BotHost

1. В переменных окружения сервиса BotHost задайте `PLATEGA_MERCHANT_ID`
   и `PLATEGA_SECRET` из одобренного магазина Platega. Секрет не храните
   в GitHub, сообщениях бота или публичных файлах. Перезапустите бота.
2. Без публичного HTTPS-адреса оставьте `PLATEGA_CALLBACK_BASE` незаданной.
   Бот автоматически проверяет ожидающие оплаты через API Platega примерно
   каждые 30 секунд. После перезапуска он также проверяет сохранённые счета.
   Интервал можно задать `PLATEGA_POLL_INTERVAL` (минимум 15 секунд).
3. Если BotHost предоставляет публичный HTTPS-адрес и перенаправление на порт
   HTTP-сервера, задайте `PLATEGA_CALLBACK_BASE=https://ваш-домен` и локальный
   `PLATEGA_CALLBACK_PORT` (по умолчанию 8080). В кабинете Platega укажите
   Callback URL `https://ваш-домен/platega/callback`. Убедитесь, что прокси
   сохраняет заголовки `X-MerchantId` и `X-Secret`. Это дополнение к опросу API.
4. Проверьте создание счёта через «Пополнить баланс», проведите контрольную
   оплату и убедитесь, что баланс увеличился ровно один раз. Повторная проверка
   статуса или повторное уведомление не должны начислять деньги повторно.

Текущий способ создания счёта — СБП, `paymentMethod=2`; доступность метода
зависит от настроек мерчанта. Отмена и истечение счёта не увеличивают баланс.
Подтверждение, зачисление и реферальный бонус сохраняются одной транзакцией
SQLite. Уведомление пользователя отправляется после сохранения.

Локальные тесты используют подменённый API и временную SQLite, без реальных
платежей. Контрольная оплата в вашем магазине остаётся обязательной проверкой
после настройки ключей на хостинге. Для старых платежей, отмеченных CONFIRMED
ещё до исправления атомарности, сверяйте баланс и журнал вручную: автоматическое
повторное начисление для них не выполняется.
