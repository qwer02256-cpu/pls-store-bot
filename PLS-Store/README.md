# PLS Store

Telegram-магазин цифровых товаров на **aiogram 3** + **SQLite** + **Platega**.

[![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/downloads/)
[![aiogram 3](https://img.shields.io/badge/aiogram-3.x-blue.svg)](https://docs.aiogram.dev/)

## Возможности

- 🛒 Каталог товаров с карточками, фото, описанием, статьёй и видео
- 💳 **Platega** — пополнение внутреннего баланса (СБП / карты)
- 👤 Профиль: баланс, потрачено, покупки, рефералы
- 🛒 Оплата с баланса, доплата недостающей суммы через Platega и автоматическая выдача файла, ключа и инструкции
- 🔑 Бессрочные лицензии, привязка FunPay, блокировка и кабинет покупателя
- 🔗 Реферальная система (% от пополнений)
- 🎟 Промокоды
- ❓ FAQ с краткими ответами и отдельной страницей «📄 Документы» (политика конфиденциальности, пользовательское соглашение, товары и тарифы)
- 🎨 Полностью настраиваемые тексты кнопок и разделов через админку
- 🖼 Баннеры для главного меню, профиля, магазина, FAQ, пополнения
- 🛠 Админ-панель: товары, заявки, платежи, пользователи, балансы, покупки, промо, FAQ, дизайн

## Статья AutoStars и краткое описание

Краткое описание устанавливается в карточку AutoStars при первом запуске
этого обновления. В карточке отображается **📄 Статья: жми**,
где только «жми» является ссылкой, без отдельной кнопки и длинного URL.
Исходники: [статья](docs/AUTOSTARS_ARTICLE.md) и [структурированный текст](docs/AUTOSTARS_ARTICLE.json).

При запуске магазин в фоне публикует статью в Telegraph и записывает ссылку
в карточку. Нужен исходящий HTTPS-доступ к `api.telegra.ph` с BotHost; отдельный
сервер и API-ключ не нужны. При недоступности Telegraph текст остаётся в исходниках магазина; ссылка
в карточке появится после успешной публикации. Публикация не задерживает запуск магазина. Аккаунт и опубликованная
страница сохраняются в SQLite; не удаляйте базу. Учетные данные публикации
не выводятся в ссылки, сообщения или журналы. Если ответ публикации потерян,
магазин сначала ищет страницу в сохранённом аккаунте.

`/admin` → Товары → AutoStars → **Описание** меняет краткий текст,
**Ссылка на статью** позволяет указать свою HTTPS-ссылку; `-` очищает её.
Правки администратора после установки этого обновления сохраняются.
Отправка в GitHub не обновляет BotHost: изменения появятся после развёртывания
и перезапуска магазина.

## Переменные окружения

| Переменная | Описание |
|------------|----------|
| `BOT_TOKEN` | Токен бота от @BotFather |
| `ADMIN_ID` | Ваш Telegram user ID |
| `SUPPORT_USERNAME` | Username поддержки (без @) |
| `REVIEWS_URL` | Ссылка на отзывы |
| `DB_PATH` | Путь к SQLite (по умолчанию `data/store.db`) |
| `PLATEGA_MERCHANT_ID` | UUID мерчанта из кабинета Platega |
| `PLATEGA_SECRET` | Секретный ключ Platega |
| `PLATEGA_CALLBACK_BASE` | Публичный HTTPS URL (например `https://bot.example.com`) |
| `PLATEGA_CALLBACK_PORT` | Порт локального HTTP-сервера колбэков (по умолчанию `8080`) |

См. `.env.example`.

## Platega

1. Получите `MerchantId` и `Secret` в [кабинете Platega](https://platega.io).
2. Укажите Callback URL:
   ```
   https://ваш-домен/platega/callback
   ```
3. Бот поднимает aiohttp-сервер на `PLATEGA_CALLBACK_PORT` и принимает POST с заголовками `X-MerchantId` / `X-Secret`.
4. При статусе `CONFIRMED` сумма идемпотентно зачисляется на баланс пользователя.

Официальная документация: https://docs.platega.io/

## FAQ и документы

В FAQ → **Документы** и на первом входе доступны четыре документа
редакции от 13 ноября 2026 года:

- [Политика конфиденциальности](docs/legal/privacy.md)
- [Пользовательское соглашение](docs/legal/agreement.md)
- [Лицензионное соглашение](docs/legal/license.md)
- [Товары и тарифы](docs/legal/terms.md)

Лицензионное соглашение общее для всех программ и плагинов магазина: в нём
нет названий отдельных товаров, конкретных кошельков и их настроек. Требования
конкретного товара остаются в его карточке, тарифах и инструкции. Все четыре
документа уточнены: основания обработки данных, процедура обращений, выдача,
объём прав, совместимость, ответственность и возвраты.

В каждом документе есть ссылки на остальные. Внизу каждой карточки товара
размещена ссылка на лицензионное соглашение. Статья, цена и соглашение
разделены пустыми строками. Пустая подпись отзывов не создаёт отдельный значок.
Для соглашения используется опубликованный анимированный значок документа
из набора магазина (если отдельный свиток не загружен). Каталог показывает название и цену
без номера версии; техническая версия файла сохранена для администрирования.

Текущие документы обслуживаются существующим aiohttp-сервером по маршрутам
`/documents/privacy`, `/documents/agreement`, `/documents/license`, `/documents/terms`.
Используется публичная база `LICENSE_PUBLIC_BASE` (либо `PLATEGA_CALLBACK_BASE`),
уже настроенная для лицензий. Если публичный адрес не настроен, ссылки открывают
тексты в боте через `/start doc_license` и аналогичные команды. Читать документы
можно до принятия условий. Нажатие «Принимаю условия» сохраняет дату и редакцию;
прошлые отметки принятия не сбрасываются и не получают новую редакцию задним числом.

После развёртывания один раз заменяются прежние ссылки документов на актуальные;
старые значения сохраняются в SQLite. В фоне публикуются новые страницы Telegraph,
с восстановлением страницы при потере ответа. Если Telegraph недоступен, остаются
локальные страницы/тексты бота. Ранее опубликованные чужие Telegraph-страницы
не редактируются — магазин получает новые ссылки. Последующие изменения ссылок
через **Админка → Дизайн** сохраняются при перезапуске.

### Premium Emoji в кнопках

Для Premium Emoji в кнопках требуется aiogram 3.25.0 или новее и Telegram Bot API 9.4+.
Откройте `Админ-панель → Дизайн → нужная кнопка` и отправьте сообщение с Premium Emoji
(можно вместе с текстом). Бот сохранит ID эмодзи отдельно и передаст его в поле
`icon_custom_emoji_id`, чтобы Telegram показывал эмодзи как иконку слева от текста кнопки.
Владелец бота должен иметь Telegram Premium (либо бот должен соответствовать условию
с дополнительными именами пользователя, приобретёнными через Fragment).

## Языки интерфейса

В главном меню добавлен выбор языка: русский и English. Выбор сохраняется отдельно для каждого Telegram-пользователя в SQLite; новые пользователи получают русский язык по умолчанию. Переключение применяется сразу, без перезапуска бота. Для существующей базы данных поле `users.language` добавляется автоматически при запуске.

## Команда администратора

Команда `/admin` отображается только в списке команд Telegram для ID, указанного в `ADMIN_ID`. Обычным пользователям показываются только публичные команды. Административные команды и обработчики дополнительно проверяют Telegram ID на сервере; скрытие команды в интерфейсе не является единственной защитой.

## Анимированные эмодзи PLS Store

При запуске бот получает `custom_emoji_id` из опубликованного набора
`https://t.me/addemoji/PLSstoreemoje`. Цветные флаги дополнительно загружаются
из `https://t.me/addemoji/PLSStoreFlags` с приоритетом над флагами основного
набора. Флаги с `needs_repainting=true` пропускаются, чтобы они не превращались
в одноцветные прямоугольники. Совпадающие обычные эмодзи заменяются
в HTML-сообщениях, подписях баннеров и иконках inline-кнопок.
ID сохраняются в SQLite; при временной недоступности набора используются
сохранённые значения, а при первом запуске — обычные эмодзи.

После добавления новых эмодзи в набор администратор может отправить
`/syncemojis`, затем открыть меню заново. Старые сообщения автоматически
не обновляются. Для другого набора или нескольких наборов задайте
`CUSTOM_EMOJI_PACKS` (имена или ссылки через запятую). Сопоставление идёт
по обычному эмодзи, назначенному при загрузке в @Stickers.

Проверка модуля: из `PLS-Store` запустите
`pip install -r requirements-test.txt`, затем `python -m unittest discover -s tests -v`.

## Настройка оплаты Platega на BotHost

1. В переменных окружения сервиса BotHost задайте `PLATEGA_MERCHANT_ID`
   и `PLATEGA_SECRET` из одобренного магазина Platega. Секрет не храните
   в GitHub, сообщениях бота или публичных файлах. Перезапустите бота.
2. Без публичного HTTPS-адреса оставьте `PLATEGA_CALLBACK_BASE` незаданной.
   Бот автоматически проверяет ожидающие оплаты через API Platega примерно
   каждые 30 секунд. После перезапуска он также проверяет сохранённые счета.
   Интервал можно задать `PLATEGA_POLL_INTERVAL` (минимум 15 секунд).
3. Если BotHost предоставляет публичный HTTPS-адрес и перенаправление на порт
   HTTP-сервера, задайте `PLATEGA_CALLBACK_BASE=https://ваш-домен` и локальный
   `PLATEGA_CALLBACK_PORT` (по умолчанию 8080). В кабинете Platega укажите
   Callback URL `https://ваш-домен/platega/callback`. Убедитесь, что прокси
   сохраняет заголовки `X-MerchantId` и `X-Secret`. Это дополнение к опросу API.
4. Проверьте создание счёта через «Пополнить баланс», проведите контрольную
   оплату и убедитесь, что баланс увеличился ровно один раз. Повторная проверка
   статуса или повторное уведомление не должны начислять деньги повторно.

После выбора суммы доступны два способа: СБП (`paymentMethod=2`, комиссия
покупателя 8,5%) и криптовалюта (`paymentMethod=13`, комиссия покупателя 5%).
Ставки соответствуют предоставленным настройкам мерчанта; при их изменении
обновите `services/payment_options.py`. Итог к оплате показывает Platega;
бот не добавляет комиссию к сумме баланса и не удерживает её повторно. Отмена и истечение счёта не увеличивают баланс.
Подтверждение, зачисление и реферальный бонус сохраняются одной транзакцией
SQLite. Уведомление пользователя отправляется после сохранения.

Локальные тесты используют подменённый API и временную SQLite, без реальных
платежей. Контрольная оплата в вашем магазине остаётся обязательной проверкой
после настройки ключей на хостинге. Для старых платежей, отмеченных CONFIRMED
ещё до исправления атомарности, сверяйте баланс и журнал вручную: автоматическое
повторное начисление для них не выполняется.

Если сумма подтверждённого платежа Platega выше суммы счёта (например, из-за
доплаты плательщика), на баланс зачисляется только исходная сумма счёта.
Платёж меньше суммы счёта не зачисляется. Для счёта 1 ₽ и подтверждения
1,09 ₽ баланс увеличится на 1 ₽; повторные проверки не изменят его.

## Прямая оплата плагинов

В карточке плагина «Купить» сразу открывает выбор СБП (8,5%) или криптовалюты
(5%). Далее создаётся отдельный счёт на товар. Пополнять внутренний баланс
перед покупкой не требуется; кнопка ручной заявки убрана.

Сумма и название товара сохраняются в счёте. После подтверждения оплаты
покупка, статистика пользователя, заказ и статус платежа записываются одной
транзакцией SQLite; баланс пользователя не изменяется. Повторное уведомление
не создаёт вторую покупку. Изменение цены/названия в каталоге после создания
счёта не меняет уже выставленный счёт. База мигрирует автоматически при запуске;
прежние счета на пополнение остаются пополнениями.

Новый баннер категории: `assets/plugins.png`. Его можно заменить через
«Админка → Баннеры → plugins». Старые кнопки покупки и ручной заявки ведут
на новый выбор способов оплаты.

Покупатель и администратор получают уведомление об оплаченной покупке.
Автоматическая отправка файла плагина этим изменением не добавляется:
сейчас продавец передаёт файл отдельно, а «Мои покупки» хранит запись покупки.

## Документы при первом входе

Первый `/start` показывает три прямые ссылки на документы и зелёную кнопку
принятия условий. Пустая настройка `license_url` не скрывает документы.
Принятие сохраняется в SQLite; повторно показывать этот экран существующим
пользователям не требуется. Экран переведён на RU/UK/EN, иконки берутся
из подключённого custom emoji пака (если соответствующие эмодзи опубликованы).

Ссылки общие для первого входа и FAQ. Изменить их можно через
«Админка → Дизайн → URL: политика / соглашение / товары и тарифы».
Принимаются полные HTTPS-ссылки. По умолчанию используются ранее указанные
страницы telegra.ph; их содержимое и внешнюю доступность нужно проверить
в браузере владельца магазина. Кнопка принятия фиксирует действие пользователя,
но не проверяет, прочитал ли он внешние страницы.

Администратор может отправить `/testdocs`, чтобы открыть экран первого входа
повторно и проверить ссылки и анимированные эмодзи. Команда не сбрасывает
сохранённое принятие условий и добавлена в список команд администратора.

Присланные ориентиры для оформления документов:
[политика](https://telegra.ph/Politika-konfidencialnosti-08-01-83) и
[соглашение](https://telegra.ph/Polzovatelskoe-soglashenie-08-01-39).
Содержимое этих страниц недоступно из среды разработки (403 прокси);
тексты магазина составлены самостоятельно, без заявления об их копировании.
